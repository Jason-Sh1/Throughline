# Accessibility checklist (WCAG 2.2 AA)

What the reader UI does for each requirement, and how it was checked. "Checked" means
looked at or measured on 2026-11-24 against a production build with the sample
edition. Items marked **not checked yet** need a person with the tool named.

## Checked

| Requirement | What the app does | How it was checked |
|---|---|---|
| 1.1.1 Non-text content | The coverage plot has a text alternative listing every count ("Left 5, Lean left 7, …") and the same numbers are printed under it. Icons are decorative (`aria-hidden`) and sit next to text or inside a labeled control. | Read the rendered markup |
| 1.3.1 Info and relationships | One `h1` per page, sections are `h2`, framing groups `h3`. Lists are real lists; the glossary is a `dl`; timestamps are `time`. | Read the rendered markup |
| 1.4.1 Use of color | Ratings are never shown by color: position, a printed label and a printed count carry them, and "Not rated" has a different dot shape. Links inside text are underlined or carry an arrow; headlines that are links (Today, "next story") and the wordmark are not underlined at rest and rely on being headlines. | Screenshots in light mode; dark mode from the tokens only |
| 1.4.3 Contrast (text) | Lowest text pair in use is 6.4:1 in light mode and 6.3:1 in dark mode (see table below). | Computed from the color tokens |
| 1.4.4 / 1.4.10 Resize and reflow | Sizes are in rem; the layout is one column from 320px up with no horizontal scrolling. | Browser at 390px and 1280px |
| 1.4.12 Text spacing | No fixed heights on text containers. | Read the styles |
| 2.1.1 Keyboard | Everything is a link, a `button`, a `details/summary` or a `dialog`. The sentence itself is an extra pointer target; its source numbers are the keyboard control. | Read the markup; dialog opened and closed in a browser |
| 2.1.2 No keyboard trap / 2.4.3 Focus order | The sheet is a native `dialog`. Below 72rem it is modal: focus moves into it, Tab stays inside, Escape closes it, focus returns to the control that opened it, and the page behind does not scroll. From 72rem it opens beside the text without trapping focus; Escape still closes it. The note is rendered before the dialog opens, so focus lands on real content. | Native browser behavior; opened and closed in Chromium |
| 2.4.1 Bypass blocks | "Skip to content" link, first in the tab order. | Read the markup |
| 2.4.2 Page titled | Every page has its own title (the story headline on story pages). | Browser |
| 2.4.4 Link purpose | "Full briefing" links carry the headline for screen readers; source links say which outlet they open, and that it is a new tab. | Read the markup |
| 2.4.7 Focus visible | 2px outline in annotation green on every focusable element. | Read the styles |
| 2.5.8 Target size | Every target meets the 24px AA minimum. The main actions ("Full briefing", back links, Close, footer links, section headers) are at least 44px high. Source numbers look small but have an enlarged hit area. Headline links and source headline links are as tall as their text (21px or more per line, with clear space around). The masthead progress marks are not interactive. | Read the styles |
| 2.3.3 / motion | Three small animations (sheet entering, highlight swipe, a section's chevron turning), all off under `prefers-reduced-motion`. Nothing moves on page load, nothing autoplays. | Read the styles |
| 3.1.1 Language | `lang="en"` on the page. | Read the markup |
| 3.2.x Predictable | Three depths only: edition, story, one sheet. Opening a sheet never navigates. | Browser |
| 4.1.2 Name, role, value / 2.5.3 Label in name | Source-number buttons are named with the numbers they show and the outlets ("Sources 2, 5: CNBC, The Times of India") and say they open a dialog; glossary terms announce "show definition"; the sheet is labeled by its heading. Section titles are `h2` inside `summary`; some screen readers do not announce headings there (to confirm in the screen-reader pass). | Read the markup |

### Contrast, measured

Computed from the OKLCH tokens in `web/src/app/globals.css` (WCAG relative luminance).
AA needs 4.5:1 for text.

| Text on ground | Light | Dark |
|---|---|---|
| ink on paper (body text) | 15.9 | 15.0 |
| secondary text on paper | 7.7 | 8.0 |
| annotation green on paper (links, source numbers) | 7.4 | 10.7 |
| ink on the sheet | 14.7 | 13.5 |
| secondary text on the sheet | 7.2 | 7.2 |
| annotation green on the sheet | 6.8 | 9.6 |
| ink on marker yellow (highlighted sentence) | 13.9 | 6.3 |
| annotation green on its hover wash | 6.5 | 7.8 |

Source numbers inside a highlighted sentence switch from green to ink, because green
on marker yellow measured 4.47:1 in dark mode, just under the limit.

Hairline rules (1.5:1 to 1.7:1 against the page) are decoration between items; no
control or meaning depends on seeing them, so 1.4.11 does not apply to them. Control
borders (the "Developing" tag, plot dots, progress marks) use ink or secondary ink.

## Not checked yet

- **Screen reader pass** with VoiceOver (iOS) and NVDA (Windows): reading order of a
  story, the sheet's announcement, the coverage plot's alternative.
- **Real phones**: tap targets and the bottom sheet on a small iPhone and an Android
  phone, including with large system text.
- **200% zoom** and Windows high-contrast mode.
- **Automated scan** (axe or Lighthouse). Not run yet; it would be a good CI step
  once the app is deployed.

## Rules for new work

1. Never show a rating, a side or a status by color alone.
2. A sentence people can tap also needs a real button for keyboards and screen readers.
3. One overlay deep, and it is always a native `dialog`.
4. New color pairs go through the contrast table above before they ship.
